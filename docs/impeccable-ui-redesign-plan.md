## 一、设计方向（需你确认的关键决策）

### 1.1 主题：暗色 → QQ 浅色

现状是暗色（`--bg-primary: #0a0e1a`）。你给的 QQ 参考图（图 1 好友管理器、图 2 消息列表）是**白底浅色**，这是“仿照 QQ”最直接的视觉信号。因此本计划默认把主窗口切到 QQ 式浅色：

- 内容区近白 `#ffffff`，面板/侧栏浅灰 `#f6f7f9`，细分割线 `#e6e8eb`。
- 主色用 QQ 蓝：`--accent: #1e9fff`（选中/主按钮/自己气泡），深蓝 `--accent-strong: #0099ff`。
- 选中态用淡蓝 `rgba(30,159,255,0.12)`，未读徽章红 `#fa5151`，在线绿 `#07c160`。

> ⚠️ **待确认**：是否接受整体切到浅色？如果你其实想保留暗色、只是把图标改圆，请告诉我，我会按“暗色 + 圆形 + QQ 样式”调整方向（改动会小很多）。

### 1.2 范围：仅主窗口，登录页不动

登录页已有独立的 `login.css` / `--lp-*` 体系（mint 深色），这次不动它，避免连坐。切浅色后需确保登录页不受全局 token 影响（保留其私有 token）。

> ⚠️ **待确认**：登录页是否也一并改成 QQ 浅色？默认不改，只做“确保不破”。

### 1.3 视觉基准：跟随 QQ，而非自创风格

按 impeccable 的“brief 优先”原则，你已把方向钉死为 QQ，所以不走概念抽签，直接以 QQ 桌面端为准做**高保真重建**，同时保持“可辨识的熟悉感”而非照抄（遵循 Operate 模式的“产品去噪测试”：熟悉但不违和）。

## 二、信息架构重构（功能按钮的改造）

### 2.1 左栏（Sidebar）——收敛为**聚焦导航**

把现在条数过多、职责分散的按钮收敛成清晰的上下两段：

**顶部**
- 当前账号头像（圆形）→ 账号切换器（保留）
- 分隔线

**主体**
- **按钮 1：消息** `MessageIcon` → 消息面板（现在聊天视图）
- **按钮 2：联系人（管理）** `UsersIcon` → 联系人管理中心（见 2.3）
- （可选）按钮 3：收藏/动态 —— 本期默认不做，如需可加
- 管理员：管理后台入口（仅 `role==='admin'`）

**底部**
- 个人资料 → 资料面板
- 退出登录

**删除的左栏按钮**：独立的“添加好友”“创建群聊”不再占用左栏。它们移入联系人管理中心（2.3）。

> 设计细节：导航项为**圆形**底（≈44–48px 圆形），图标居中 `currentColor`；选中态 = 主色填充 + 白色图标 + 左缘一条蓝色竖条（QQ 式）；未读红点为圆形徽章。移除现有 `.nav-item-qq` 的 `border-radius:16px` 方角。

### 2.2 消息面板（ConversationList）——只放消息

- 头部：标题“消息” + 搜索框 + 右上圆角 **“+”** 按钮。
- 列表：仅会话（私聊 + 群聊混排，按最近消息排序、置顶优先，逻辑不变）。
- 头像改**圆形**，未读红点、免打扰灰点、在线点保留。
- **移除列表顶部的“新朋友”固定入口** → 移到联系人管理中心（好友通知）。
- “+” 按钮：默认给出一个小菜单（加好友 / 创建群聊 / 发消息），作为快捷入口；核心归口仍是联系人管理中心。

> ⚠️ **待确认**：消息面板顶部的“+”是做成小下拉菜单（加好友/建群聊），还是直接跳到联系人管理中心？默认做**小下拉**，更顺手。

### 2.3 联系人管理中心（新面板）——把群聊 + 联系人管理收拢

由左栏“按钮 2”触发，替换现有 `FriendList` 与 Sidebar 里的两个弹窗，做成 QQ 式“好友管理器”：

**面板结构（自上而下）**
1. 标题“联系人” / 搜索框 / 右上 **“+”**（加好友）。
2. **“好友管理器”** 主入口卡（QQ 同款，可点击进入管理视图）。
3. 两行入口：**“好友通知”**（带待处理数徽章 → 展开好友申请，支持同意/忽略）、**“群通知”**（本期为占位空态，见 §7）。
4. 分段控件：**“好友 / 群聊”**。
5. **好友 Tab**：好友列表（圆形头像 + 在线点 + 搜索过滤 + 右键：发消息 / 看资料 / 删好友；空态提示）。分组：数据源无自定义分组，先按“我的好友”单组展示。
6. **群聊 Tab**：我的群聊列表（从群聊会话推导，见 §7）+ “创建群聊”按钮（原 Sidebar 弹窗移入此处）+ 群管理（公告 / 成员）。

**功能归口变化**
- 原 Sidebar“添加好友”弹窗 → 移入本面板（好友通知 / “+”）。
- 原 Sidebar“创建群聊”弹窗 → 移入本面板（群聊 Tab）。
- 原 FriendList → 升级为本面板的好友 Tab，并叠加好友通知、群聊 Tab。

## 三、设计令牌（QQ 浅色）

重写 `web/src/index.css` 的 `:root` 令牌（保留登录页独立 token），新增/调整：

```css
:root {
  /* 背景 */
  --bg-app: #ffffff;        /* 内容区/聊天区 */
  --bg-panel: #f6f7f9;      /* 左栏、列表面板 */
  --bg-hover: #f0f2f5;
  --bg-active: #eaf2ff;     /* 选中行淡蓝 */
  --bg-input: #f2f3f5;
  --bg-elevated: #ffffff;

  /* 文字 */
  --text-primary: #1f2329;
  --text-secondary: #5f6368;
  --text-muted: #9aa0a8;

  /* 主色（QQ 蓝） */
  --accent: #1e9fff;
  --accent-strong: #0099ff;
  --accent-soft: rgba(30, 159, 255, 0.12);

  /* 语义色 */
  --success: #07c160;
  --danger: #fa5151;
  --warning: #ff9f0a;
  --online: #07c160;
  --offline: #c9cdd4;

  /* 边框 */
  --border: #e6e8eb;
  --border-light: #eef0f2;

  /* 消息气泡（QQ 式） */
  --bubble-mine: #1e9fff;
  --bubble-mine-text: #ffffff;
  --bubble-other: #ffffff;
  --bubble-other-text: #1f2329;

  /* 阴影（浅色更轻） */
  --shadow-sm: 0 1px 3px rgba(0, 0, 0, 0.06);
  --shadow-md: 0 4px 12px rgba(0, 0, 0, 0.08);
  --shadow-lg: 0 12px 32px rgba(0, 0, 0, 0.12);
}

/* 圆形：头像/图标/导航 */
--radius-full: 50%;
```

**圆形化规则**
- 头像一律 `border-radius: 50%`（社交头像 `sm=32/md=44/lg=64`，根据视觉密度定，避免旧版的 28/36 方形）。
- 左侧导航图标按钮为圆形底；未读/在线/免打扰点均为圆形。
- 群头像：彩色圆底 + 群图标（`UsersIcon`），私聊头像：彩色圆底 + 首字母（保留现有哈希取色）。
- 卡片/输入框/按钮：保留适度圆角（QQ 用 8–12px），但**头像与图标必须圆形**（这是本次“圆形而非圆角矩形”的核心）。

## 七、数据依赖与风险

1. **“我的群聊”无后端接口**：前端 `api/groups.ts` 只有创建/详情/更新/成员，没有“列出我加入的群”。本期方案**从会话列表推导**（`conversations.filter(type==='group')` 的 `group_id` + `groupDetails`）。若你想要精确的“我加入的群 + 角色”，需后端加 `GET /groups/mine`，本期不动后端。
   - ⚠️ **待确认**：接受“前端从会话推导”即可，还是要我加一个后端接口？
2. **“群通知”无数据模型**：本期该行只做入口 + 空态占位，不虚构通知数据。真实群通知流需要新数据表/接口，不在本期。
3. **浅色与登录页联动**：`body` 与 `.chat-layout` 用全局 `--bg-primary`，改成浅色后需确认登录页容器自带上色，不依赖全局白。
4. **配色权重**：QQ 蓝属于“熟悉且有效”的落地方向，我会做得克制——主色只用于选中/主按钮/自己气泡，不做大面积装饰性用色。
